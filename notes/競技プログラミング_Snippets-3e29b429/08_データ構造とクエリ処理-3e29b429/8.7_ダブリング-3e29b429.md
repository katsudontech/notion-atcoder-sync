# 8.7 ダブリング

Source: https://www.notion.so/3e29b4299e6181168d18d76cd038fed4

---

<callout icon="💡" color="blue_bg">
	ダブリングは、**同じルールの移動をK回繰り返した結果**を高速に求める方法。1回・2回・4回・8回…先を前計算し、Kの二進数表現で組み合わせる。最短経路を探す手法ではない。
</callout>
このページでは、0-indexedのPythonコードで「到着位置だけ」と「途中の合計も必要」の2パターンを扱う。基本版から読み、合計・木の祖先は必要になったときに使えばよい。

前提は「状態vが決まれば、次の状態nxt\[v\]が常に一意に決まる」こと。一般のグラフの隣接リストではなく、長さNの遷移配列を用意する。サイクルや自己ループがあっても問題ない。
## 仕組み：2の累乗回先を保存する
`jump[j][v]` は、状態vから `2**j` 回移動した先の状態番号。
```python
jump[0][v] = nxt[v]                       # 1回先
jump[j + 1][v] = jump[j][jump[j][v]]       # 前半2**j回 + 後半2**j回
```
まず2の累乗回だけ進んだ「中間地点」を求め、その地点から同じ回数だけ進めば、移動回数が2倍になる。行き先の番号自体を2倍するわけではない。
### 具体例
`nxt = [1, 2, 3, 4, 0]`、つまり `0→1→2→3→4→0` の場合。

13回なら `13 = 8 + 4 + 1`。二進数では `0b1101` なので、0・2・3ビット目の行だけ使う。下位ビットから使う場合、状態0から1回で1、さらに4回で0、さらに8回で3に到着する。
## 実戦テンプレ：前計算と問い合わせを分ける
前提：`N >= 1`、`len(nxt) == N`、すべての行き先が `0 <= nxt[v] < N`。`max_k >= 0` とし、各クエリは `0 <= k <= max_k`、`0 <= start < N` で使う。行き先なしの `-1` を直接渡してはいけない。
```python
def build_doubling(nxt, max_k):
    """nxt[v]: vから1回移動した先。0-indexed。
    max_k: 問い合わせる移動回数の最大値（0以上）。
    戻り値 jump[j][v]: vから2**j回移動した先。
    """
    if max_k < 0:
        raise ValueError("max_k must be non-negative")

    n = len(nxt)
    log = max(1, max_k.bit_length())
    jump = [list(nxt)]

    for _ in range(1, log):
        prev = jump[-1]
        jump.append([prev[prev[v]] for v in range(n)])

    return jump


def kth_next(jump, start, k):
    """startからk回移動した先を返す。k=0ならstart。"""
    if k < 0 or k.bit_length() > len(jump):
        raise ValueError("k is negative or exceeds the table capacity")

    v = start
    bit = 0
    while k:
        if k & 1:
            v = jump[bit][v]
        k >>= 1
        bit += 1

    return v
```
### 戻り値と使い方
- `build_doubling(nxt, max_k)` → 使い回す前計算表 `jump`
- `kth_next(jump, start, k)` → k回移動した後の状態番号
- `k=0` のときは1回も移動せず、開始位置を返す
```python
nxt = [1, 2, 3, 4, 0]  # 0→1→2→3→4→0 のサイクル
jump = build_doubling(nxt, 13)

print(kth_next(jump, 0, 13))  # 3
print(kth_next(jump, 0, 0))   # 0
print(kth_next(jump, 2, 4))   # 1
```
`k & 1` は「現在見ている最下位ビットが1か」、`k >>= 1` は「そのビットを消して次へ進む」操作。ビットが1のときだけ、その時点の位置vから `2**bit` 回ぶんジャンプする。
### 表の段数はNではなく最大Kで決める
`log = max(1, max_k.bit_length())` とする。たとえば最大Kが `10**18` なら60段。Nが小さくてもサイクルを何度も回るため、`N.bit_length()` では足りない場合がある。
`max_k=0` でも扱えるよう最低1段を作っている。後から表のビット数で表せないKを渡すと、テンプレートは `ValueError` を出す。問い合わせの最大Kを含めて前計算すること。
### 入力付きの適用例：鉄則 A57
[A57 - Doubling（公式問題）](https://atcoder.jp/contests/tessoku-book/tasks/tessoku_book_be)のように、開始位置と移動回数の組を多数処理する形。**上の2関数の下に追加するコード**。
```python
import sys
input = sys.stdin.readline

N, Q = map(int, input().split())
nxt = [int(x) - 1 for x in input().split()]
queries = [tuple(map(int, input().split())) for _ in range(Q)]

max_k = max((k for _, k in queries), default=0)
jump = build_doubling(nxt, max_k)

answers = []
for start, k in queries:
    goal = kth_next(jump, start - 1, k)
    answers.append(str(goal + 1))

print("\n".join(answers))
```
入力の頂点番号は1-indexed、内部は0-indexedに統一する。`nxt` と開始位置の両方を1引き、出力で1を足す。前計算はクエリごとに作り直さない。
## 実戦テンプレ：移動先と合計を返す
次は基本版とは独立して使える2関数。`weight[v]` を「vから1回出発するときに得る値」と定義する。
- `jump[j][v]`：vから `2**j` 回移動した先
- `gain[j][v]`：その `2**j` 回の移動で得る合計
- 中間地点を `mid = jump[j][v]` とすると、次の段の合計は `gain[j][v] + gain[j][mid]`
前提は基本版と同じで、さらに `len(weight) == len(nxt)`。ここでは整数の重みを想定する。移動規則と重みが固定なら、負の重みでも合計の計算はできる。
```python
def build_doubling_sum(nxt, weight, max_k):
    """weight[v]: vから1回出発するときに得る値。
    戻り値: jump（移動先の表）, gain（合計の表）。
    """
    if max_k < 0:
        raise ValueError("max_k must be non-negative")

    n = len(nxt)
    log = max(1, max_k.bit_length())
    jump = [list(nxt)]
    gain = [list(weight)]

    for _ in range(1, log):
        prev_jump = jump[-1]
        prev_gain = gain[-1]

        jump.append([prev_jump[prev_jump[v]] for v in range(n)])
        gain.append([
            prev_gain[v] + prev_gain[prev_jump[v]]
            for v in range(n)
        ])

    return jump, gain


def jump_with_sum(jump, gain, start, k):
    """(k回移動後の位置, k回の移動で得た合計)を返す。"""
    if k < 0 or k.bit_length() > len(jump):
        raise ValueError("k is negative or exceeds the table capacity")

    v = start
    total = 0
    bit = 0

    while k:
        if k & 1:
            # 必ず移動前のvで合計を取得する
            total += gain[bit][v]
            v = jump[bit][v]
        k >>= 1
        bit += 1

    return v, total
```
### 使用例と数える範囲
```python
nxt = [1, 2, 0]
weight = [10, 20, 30]
jump, gain = build_doubling_sum(nxt, weight, 4)

print(jump_with_sum(jump, gain, 0, 4))  # (1, 70)
print(jump_with_sum(jump, gain, 0, 0))  # (0, 0)
```
4回の移動は `0→1→2→0→1`。出発した状態は0・1・2・0なので、合計は `10+20+30+10=70`。**最終到着地点の重みを追加では数えない**。同じ状態でも通るたびに加算する。
`k=0` の戻り値は `(start, 0)`。到着地点の重みを加算するルールなら、最初に `weight[v] = value[nxt[v]]` に相当する配列を作って渡す。
### 適用例：状態が「合計の余り」になる問題
[ABC241 E - Putting Candies（公式問題）](https://atcoder.jp/contests/abc241/tasks/abc241_e)の操作は `X += A[X % N]`。大きくなるXそのものを状態にせず、`v = X % N` を状態にする。
状態vでの増加量は `A[v]`、次の状態は `(v + A[v]) % N`。そのため集計付きダブリングに置き換えられる。初期値Xが0のケースでは次のように呼び出す。
```python
# A, Kが与えられ、X=0から始める場合
N = len(A)
nxt = [(v + A[v]) % N for v in range(N)]

jump, gain = build_doubling_sum(nxt, A, K)
remainder, answer = jump_with_sum(jump, gain, 0, K)
print(answer)
```
余りにするのは状態だけで、答えの合計はNで割らない。大きい制約では2つの表が重くなるので、1つの開始点からの問い合わせならサイクル検出＋累積和も比較する。
### 合計以外にも拡張できる
合計の `+` を別の結合演算へ変えると、最小・最大・XORなども集計できる。

集計表を作るときとクエリに答えるときの両方で演算を変える。必要なのは結合法則と単位元で、交換法則は不要。順序がある演算では、必ず「前半→後半」「すでに求めた結果→今回の区間」の順に結合する。計算量の説明は、各結合がO(1)で済む集計を前提としている。
## 応用：木のK個上の祖先
根付き木では `nxt[v] = parent[v]` とすれば、K回移動はK個上の祖先になる。根より上に祖先がない場合も扱うには、番兵となる架空の状態Nを追加する。
番兵は `nxt[N] = N` とし、一度到達したらそこに留める。これなら各状態の行き先が必ず配列内に収まる。
```python
# 根0。parent[v]はvの親、親なしは-1。
parent = [-1, 0, 0, 1, 1]
N = len(parent)
sentinel = N

# -1を番兵Nへ置換し、番兵は自分自身へ移動する
nxt = [p if p != -1 else sentinel for p in parent] + [sentinel]
jump = build_doubling(nxt, 3)

def kth_ancestor(v, k):
    goal = kth_next(jump, v, k)
    return -1 if goal == sentinel else goal

print(kth_ancestor(4, 2))  # 0
print(kth_ancestor(4, 3))  # -1
```
この例は基本テンプレートの2関数と併用する。一般のKに答える場合は、その最大値を `build_doubling` に渡す。
根の親を根自身にする実装もあるが、その場合は根を越えても根が返る。存在しない祖先を `-1` として区別したいなら、番兵か深さによる判定を使う。集計付きで番兵を使うなら、番兵の1回分の値を合計では0にする。
### LCAへのつながり
最小共通祖先（LCA）でも、2の累乗個上の祖先の表を使う。まず深さをそろえ、同じ頂点になったらその頂点が答え。異なる場合は、大きい段から「祖先が異なる場合だけ2頂点を同時に上げる」と、共通祖先の直下まで移動できる。ここでのK番目祖先が土台になるが、LCAには別途、深さと2頂点を扱う処理が必要。

## よくあるミス・確認事項
- `jump[j][v]` を「j回先」と勘違いする。正しくは `2**j` 回先。
- Pythonで `2 ^ j` を使う。累乗は `2 ** j` で、`^` はXOR。
- `jump[j][v]` を2倍する。必要なのは行き先の合成 `prev[prev[v]]`。
- 行数をNだけで決める。最大の移動回数Kに合わせる。
- 1-indexedの入力をそのまま0-indexedの配列へ入れる。
- `-1` をそのまま添字に使う。Pythonでは末尾の要素を指し、誤った状態へ移動してしまう。
- `[[0] * N] * B` で表を作り、全行が同じリストを共有してしまう。各行を別々に作る。
- 集計の前に `v` を書き換える。まず移動前のvで値を取得してからジャンプする。
- サイクルで再訪したときの得点を一度しか数えない。移動回数ぶん毎回加算する。
- この表から全経路のノードをO(log K)で出力できると思う。K回ぶんの経路を列挙するなら出力だけでO(K)が必要。
- 移動先や重みを更新したのに古い表を使う。ここでのテンプレートは静的な規則が前提。
