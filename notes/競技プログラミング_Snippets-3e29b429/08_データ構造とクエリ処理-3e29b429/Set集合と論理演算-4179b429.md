最初に区別すること：**論理積**は条件の「両方が成り立つ」、\*\*積集合（共通部分）\*\*は集合の「両方に入っている要素」。考え方は対応するが、Pythonで使う演算子と返るものが違う。
## 1. 論理積・論理和・否定
条件の結果は True（真）か False（偽）。
- 論理積 AND：両方が真なら真。Pythonでは `and`。
- 論理和 OR：少なくとも片方が真なら真。両方が真でもよい。Pythonでは `or`。
- 否定 NOT：真偽を逆にする。Pythonでは `not`。
- 排他的論理和 XOR：片方だけが真なら真。bool同士なら `p != q` で表せる。

```python

```
### 短絡評価
`and` は左が偽なら右を評価しない。`or` は左が真なら右を評価しない。
```python
# 先に範囲内か確認することで、範囲外アクセスを防ぐ
if 0 <= i < len(A) and A[i] == target:
    print("見つかった")
```
厳密には、Pythonの `and / or` は必ずboolを返すわけではなく、判定に使ったオペランドを返す。条件式同士なら通常boolになる。空の集合・リストや0は偽として扱われる。
## 2. 集合とsetの基本
集合は要素の集まり。Pythonの `set` は重複を持たず、添字で取り出す順序も持たない。
```python
S = {2, 3, 3, 5}  # {2, 3, 5}
empty = set()     # 空集合。{} は空の辞書
S = set([2, 3, 3, 5])

print(3 in S)     # True：含まれる
print(4 not in S) # True：含まれない
print(len(S))     # 3：異なる要素の個数
```
表示順序には意味がない。昇順で扱いたいときは `sorted(S)` でリストにする。

```python
S = {2, 3, 5}

print(S ^ T)  # {2, 4}
```
「積」という名前でも掛け算ではない。集合の補集合を `~S` と書くことはできない。
### 論理演算とのつながり
要素xごとに見ると、積集合への所属は論理積になっている。
```python
x in (S & T)  # (x in S) and (x in T) と同じ真偽
x in (S | T)  # (x in S) or (x in T) と同じ真偽
```
**人ごとに条件を調べるならand、条件を満たす人の集まりをまとめて扱うなら積集合**、と考える。

```python
S = {2, 3}
S.add(4)          # {2, 3, 4}
S.update({4, 5})  # {2, 3, 4, 5}
S &= {3, 5}      # {3, 5}：積集合で更新
S |= {6}         # {3, 5, 6}：和集合で更新
S -= {3}         # {5, 6}
S ^= {5, 7}      # {6, 7}
```
`S = S & T` は新しい集合を作ってSに代入し、`S &= T` は元の集合を更新する。Sをほかの変数からも参照している場合は違いが出る。
```python
S = {2, 3}
alias = S        # 同じ集合を見る
saved = S.copy() # 独立したコピー
S &= {3}
# alias も {3}。saved は {2, 3} のまま
```
### 今回つまずいたaddとupdate
```python
# NG：変更可能なsetを、setの要素にはできない
# S.add({a, b})  # TypeError: unhashable type: 'set'

S.update({a, b}) # 2人を追加する
S &= {a, b}     # 2人のうち、今も候補にいる人だけ残す
```
setの要素には整数・文字列など、ハッシュ可能なものを使う。ペア自体を記録するなら、整数2つのタプル `S.add((a, b))` が使える。順序を区別しないペアなら `(min(a, b), max(a, b))` に揃える。今回はペアを保存するのでなく、人の候補を絞る問題だった。
## 5. 集合の関係を判定する
```python
S = {2, 3}
T = {2, 3, 5}

print(S <= T)          # True：SはTの部分集合
print(S < T)           # True：部分集合で、同じ集合ではない
print(S == T)          # False：要素が完全に同じか
print(S.isdisjoint(T)) # False：共通要素がないか
```
setの `<` は個数の比較ではなく、包含関係の比較。個数だけなら `len(S) < len(T)`。
## 6. ド・モルガンの法則とall / any
否定を中に入れるとANDとORが入れ替わる。
```python
not (p and q)  # (not p) or (not q)
not (p or q)   # (not p) and (not q)
```
「2人のどちらもaではない」は、次のどちらでも書ける。
```python
A[i] != a and B[i] != a
not (A[i] == a or B[i] == a)
```
集合でも、全体集合Uを決めると同じ対応がある。
```python
U - (S | T)  # (U - S) & (U - T)
U - (S & T)  # (U - S) | (U - T)
```
複数の条件をまとめて判定するなら `all` と `any`。
```python
all(x > 0 for x in A) # すべて正か
any(x > 0 for x in A) # 1つ以上、正の要素があるか

all([]) # True：違反するものがない
any([]) # False：満たすものがない
```
空の場合も考える。今回「固定した人が出ていない大会が0個」なら、相方に追加条件がないので、ほかの全員が候補になる。

## 8. 競プロでどう見抜くか
- 「すべての条件を満たす候補」→ 条件ごとの候補集合の積集合。
- 「いずれかの条件を満たすもの」→ 和集合。
- 「候補から禁止対象を除く」→ 差集合。
- 「異なる値の個数」→ set化してlen。
- 「何度も存在を確認する」→ setのin。
- 「重複の回数も必要」→ setでは失われるのでCounterなどを使う。
### 初期値が重要
候補を絞る場合は、全候補から開始する。空集合から積集合を取ると、ずっと空のまま。
```python
candidates = set(range(1, N + 1))
candidates.discard(a)

for allowed in conditions:
    candidates &= allowed
```
集合の和を集める場合は、空集合から開始できる。積集合では全体集合、和集合では空集合が自然な初期値になる。
## 9. ABC469 Dでの応用と振り返り
[ABC469 D - The Big Two](https://atcoder.jp/contests/abc469/tasks/abc469_d)
N人、M大会。選んだ2人の少なくとも一方が、すべての大会で決勝に出ている組を数える。制約は N, M ≤ 2×10⁵。
### 発想の順番
1. 全ペアO(N²)は厳しい。
2. 正解の組は1回目の決勝にも対応するので、A\[0\]またはB\[0\]を必ず含む。
3. 1人aを固定する。
4. aが出た大会は条件達成済み。相手の情報は不要。
5. aが出ていない大会では、もう1人が決勝の2人のどちらかでなければならない。
6. 各大会の2人の集合との積集合で候補を絞る。
例：a=1が出ていない大会が \{2, 3\} と \{3, 4\} なら、相方は共通する3だけ。
### ACした方針を整理したコード
```python
import sys
input = sys.stdin.readline

N, M = map(int, input().split())
matches = [tuple(map(int, input().split())) for _ in range(M)]

def count_partners(a, exclude=None):
    candidates = set(range(1, N + 1))
    candidates.discard(a)
    if exclude is not None:
        candidates.discard(exclude)

    for u, v in matches:
        if u != a and v != a:
            candidates &= {u, v}

    return len(candidates)

a, b = matches[0]
ans = count_partners(a)
ans += count_partners(b, exclude=a)
print(ans)
```
2回目はaを除いて、ペア\{a, b\}の二重計上を防ぐ。aを含むペアとbを含むペアが重なるのは、この1組だけ。成立する場合は1回目で数え、成立しない場合はどちらでも数えない。
### 計算量と境界条件
時間は平均O(N + M)、空間はO(N + M)。候補集合の作成にO(N)、試合保存にO(M)。これを定数回行う。
積集合の相手は毎回2要素で、最初の絞り込み後は候補も高々2人。大きい旧集合を解放するコストを含めても全体でO(N + M)に収まる。
- aが全大会に出る：ほかの全員が候補に残る。
- 共通する人がいない：候補は空集合、0通り。
- M=1：どちらかの決勝進出者を含む組は2N−3通り。
- 同じ決勝の組が繰り返される：同じ集合との積集合なので問題ない。
- N=2：選べる組は1つ。
### 今回のミスの分類
- アルゴリズム理解：全大会を満たす必要があるのに、追加して和集合を作っていた。
- Python仕様：`add({a, b})` で変更可能な集合そのものを要素にしようとした。
- 初期値：積集合による絞り込みを空集合から始めると何も残らない。
- 改善できた点：2つの固定ケースと重複除外まで自分で実装し、ACできた。
次に持ち越す発想：**1つ固定すると、残りが満たすべき条件が見える。その条件を「全て満たす」なら積集合を疑う。**

## 11. 確認問題
S=\{1, 2, 4\}、T=\{2, 3, 4\}のとき、S & T、S - T、S \^ Tは何か？
<details>
<summary>答え</summary>
	- S & T = \{2, 4\}
	- S - T = \{1\}
	- S \^ T = \{1, 3\}
</details>
候補が\{2, 3\}で、次の条件が\{3, 4\}だったとき、「すべての条件を満たす候補」に使うのはadd、update、&のどれか？
<details>
<summary>答え</summary>
	&で共通部分を取り、\{3\}を残す。updateだと\{2, 3, 4\}になり、どれかの条件を満たした人まで残してしまう。
</details>
