## 実戦テンプレ
```python
from atcoder.segtree import SegTree


# op：区間の情報を結合する演算
# e ：opの単位元。0 + x == x
def op(a, b):
    return a + b


A = list(map(int, input().split()))
seg = SegTree(op, 0, A)
```
短く書く場合は次でもよい。
```python
seg = SegTree(lambda a, b: a + b, 0, A)
```
## 基本操作
```python
# A[p] を x に変更
seg.set(p, x)

# 現在の A[p] を取得
value = seg.get(p)

# 半開区間 [l, r) の合計
total = seg.prod(l, r)

# 全要素の合計
total_all = seg.all_prod()
```
## 一点加算
`set` は代入なので、現在値を取得してから加算する。
```python
# A[p] に x を足す
seg.set(p, seg.get(p) + x)
```
## 長さNの0配列から作る
第三引数に要素数を渡すと、単位元で初期化される。
```python
seg = SegTree(lambda a, b: a + b, 0, N)
```
## 例
```python
A = [5, 2, 8, 6, 1]
seg = SegTree(lambda a, b: a + b, 0, A)

print(seg.prod(1, 4))  # 2 + 8 + 6 = 16

seg.set(1, 7)          # A[1]を2から7へ変更

print(seg.prod(1, 4))  # 7 + 8 + 6 = 21

seg.set(2, seg.get(2) + 3)  # A[2]に3を加算

print(seg.get(2))      # 11
print(seg.all_prod())  # 30
```
## 各引数の意味
- `op(a, b)`：左右の区間情報を結合する関数。RSQでは加算
- `e`：何と結合しても結果を変えない単位元。RSQでは0
- 第三引数：初期配列、または要素数 `N`
## 使う場面
- 配列の値を更新しながら区間和を何度も求める
- 累積和では対応しにくい、途中で値が変わる問題
- 一点更新と区間クエリが大量にある
## 注意事項
- `prod(l, r)` は半開区間。添字 `r` の要素は含まれない
- `set(p, x)` は `A[p] += x` ではなく `A[p] = x`
- 一点加算は `seg.set(p, seg.get(p) + x)`
- `prod(l, l)` のような空区間では単位元0が返る
- 0-indexedで扱う
## 計算量
- 構築：O(N)
- `set`：O(log N)
- `get`：O(1)
- `prod`：O(log N)
- `all_prod`：O(1)
## よくあるミス
- 閉区間のつもりで `prod(l, r)` を呼び、右端を1つ落とす
- 一点加算で `seg.set(p, x)` と書き、元の値を消す
- RSQの単位元を `INF` にする
- 更新後も元の配列 `A` を参照し、SegTree内の値と食い違う
## 関連
- RMQ：区間最小値
- Fenwick Tree：一点加算と区間和に特化した軽量な構造
