## 1. テンプレ {toggle="true"}
	変更されない文字列の部分区間を、何度も比較するためのローリングハッシュ。前計算後は区間のハッシュ値をO(1)で取り出せる。
	共通テンプレートのsetup実行後に使う。追加のimportは不要。添字は0-indexed、区間は `[l, r)`（左端を含み、右端を含まない）に統一する。
	### 法を1つ使う版 {toggle="true"}
		`build_hash(s)` で前計算し、`get_hash(pref, power, l, r)` で `s[l:r]` のハッシュを求める。
		```python
MOD = 1_000_000_007
BASE = 911_382_323

def build_hash(s):
    n = len(s)
    power = [1] * (n + 1)
    pref = [0] * (n + 1)
    for i, ch in enumerate(s):
        power[i + 1] = power[i] * BASE % MOD
        pref[i + 1] = (pref[i] * BASE + ord(ch) + 1) % MOD
    return pref, power

def get_hash(pref, power, l, r):
    """文字列の[l, r)のハッシュを返す"""
    return (pref[r] - pref[l] * power[r - l]) % MOD
		```
	### 実戦用：二重ハッシュ版 {toggle="true"}
		異なる2つの素数で求めた値を組 `(hash1, hash2)` で返す。単一法版より衝突のリスクを下げるが、厳密な一致を保証するものではない。
		```python
class RollingHash:
    MOD1 = 1_000_000_007
    MOD2 = 1_000_000_009
    BASE = 911_382_323

    def __init__(self, s):
        n = len(s)
        self.n = n
        self.power1 = [1] * (n + 1)
        self.power2 = [1] * (n + 1)
        self.pref1 = [0] * (n + 1)
        self.pref2 = [0] * (n + 1)

        for i, ch in enumerate(s):
            x = ord(ch) + 1
            self.power1[i + 1] = self.power1[i] * self.BASE % self.MOD1
            self.power2[i + 1] = self.power2[i] * self.BASE % self.MOD2
            self.pref1[i + 1] = (self.pref1[i] * self.BASE + x) % self.MOD1
            self.pref2[i + 1] = (self.pref2[i] * self.BASE + x) % self.MOD2

    def get(self, l, r):
        """s[l:r]（0-indexed・右端は含まない）の二重ハッシュ"""
        if not 0 <= l <= r <= self.n:
            raise IndexError("invalid substring range")
        length = r - l
        x1 = (self.pref1[r] - self.pref1[l] * self.power1[length]) % self.MOD1
        x2 = (self.pref2[r] - self.pref2[l] * self.power2[length]) % self.MOD2
        return x1, x2

    def same(self, l1, r1, l2, r2):
        """同じ元文字列の2区間が一致するか（衝突の可能性あり）"""
        return r1 - l1 == r2 - l2 and self.get(l1, r1) == self.get(l2, r2)
		```
## 2. それの使い方 {toggle="true"}
	<empty-block/>
	### 単一法版の使い方 {toggle="true"}
		```python
s = "abcbabc"
pref, power = build_hash(s)
print(get_hash(pref, power, 0, 3) == get_hash(pref, power, 4, 7))
# True: "abc" == "abc"
		```
		`get_hash(pref, power, l, r)<br>は、pref, power`はビルドハッシュそのまま、lは開始、rは最後だけど、rを含まない
	### 二重ハッシュ版の基本操作 {toggle="true"}
		`RollingHash(s)` を作り、次の操作を使う。
		- `rh.get(l, r)`：`s[l:r]` の二重ハッシュを返す。
		- `rh.same(l1, r1, l2, r2)`：同じ元文字列の2区間について、長さとハッシュが一致するか調べる。
		```python
s = "abcbabc"
rh = RollingHash(s)

print(rh.same(0, 3, 4, 7))  # True  ("abc" == "abc")
print(rh.same(0, 3, 1, 4))  # False ("abc" != "bcb")
print(rh.get(0, 0))          # (0, 0)：空文字列
		```
		`s = ""` でも生成でき、`get(0, 0)` は `(0, 0)` を返す。`get` に範囲外の区間を渡すと `IndexError` になる。

			### 区間一致クエリ：鉄則 A56 {toggle="true"}
				公式問題の入力は **1-indexedで両端を含む \*\*\*\*****`[a, b]`**。`rh.same(a - 1, b, c - 1, d)` とするとPythonの半開区間に直せる。たとえば問題の1文字目から3文字目は `[0, 3)`。
				共通テンプレートのsetupと上の `RollingHash` クラスを用意し、以下を `main()` の中に置く（1段インデントする）。
				```python
N, Q = map(int, input().split())
S = input().strip()
rh = RollingHash(S)

answers = []
for _ in range(Q):
    a, b, c, d = map(int, input().split())
    # 問題の[a, b] → Pythonの[a-1, b)
    ok = rh.same(a - 1, b, c - 1, d)
    answers.append("Yes" if ok else "No")

print("\n".join(answers))
				```
				この問題では比較区間の長さが等しいと保証されているが、`same` メソッドでも長さを確かめている。
			### パターンの出現位置 {toggle="true"}
				同じ設定のクラスを本文とパターンに使えば、長さmの窓を左から順に比較できる。候補の列挙は前計算後O(N)。
				```python
s = "ababa"
t = "aba"
hs = RollingHash(s)
ht = RollingHash(t)
m = len(t)
target = ht.get(0, m)

positions = [
    i for i in range(len(s) - m + 1)
    if hs.get(i, i + m) == target
]
print(positions)  # [0, 2]
				```
				ハッシュだけで判定しているため、極めてまれに不一致の箇所も候補に入る。候補を `s[i:i+m] == t` で再確認すれば厳密になるが、候補が大量にある場合はO(Nm)まで遅くなる。常に厳密で速い方法が必要ならZ algorithmなどを選ぶ。
			### 回文判定 {toggle="true"}
				元の `s[l:r]` に対応する逆順文字列上の区間は `[n-r, n-l)`。
				```python
s = "abacaba"
n = len(s)
forward = RollingHash(s)
backward = RollingHash(s[::-1])

def is_palindrome(l, r):
    """s[l:r]が回文か（衝突の可能性あり）"""
    return forward.get(l, r) == backward.get(n - r, n - l)

print(is_palindrome(0, 7))  # True
print(is_palindrome(0, 4))  # False
				```
				複数の回文判定があるときに有効。こちらもハッシュ衝突の可能性は残る。
## 3. 使う場面 {toggle="true"}
	- 長い文字列の任意の2区間を何度も比較する。
	- 本文中でパターンと一致する部分文字列の候補を探す。
	- 元の文字列と逆順文字列を使い、部分区間の回文判定を何度も行う。
	数回の比較だけなら `s[l:r] == s[a:b]` が簡単。文字が途中で変更される問題では、この前計算表をそのまま使い回せない。
## 4. 注意事項 {toggle="true"}
	### ハッシュの一致と文字列の一致 {toggle="true"}
		同じ文字列ならハッシュは必ず同じ。ただし、**異なる文字列でも同じハッシュになる場合がある**。たとえば法が7なら、1文字の `"a"` は `(ord("a")+1)%7 = 0`、`"h"` も `(ord("h")+1)%7 = 0`。
		二重ハッシュは衝突のリスクを大幅に下げるが、ゼロにはできない。実戦では問題の要求精度を確認し、厳密な一致が必要なら実際の文字列で再確認するか、Z algorithm・KMPなど衝突しない方法を使う。
		Python組み込みの `hash(s[l:r])` は、このページの「前計算で区間ハッシュをO(1)取得」する仕組みの代わりにはならない。先に `s[l:r]` を作る処理が区間長に比例し、またPythonの文字列ハッシュは実行プロセスをまたぐと値が変わりうる。
	### 比較するときの前提 {toggle="true"}
		- 区間は `0 <= l <= r <= len(s)` を満たす半開区間にする。
		- `get` 同士を直接比較するときは、区間の長さも確認する。`same` は長さの確認も行う。
		- 別々の文字列を比較するときは、同じ基数・法・文字の数値化方法を使う。
		- 前計算後に元の文字列を変更した場合は、ハッシュを作り直す。
		- ハッシュ用の法はコード内の `MOD`・`MOD1`・`MOD2` を使う。問題の答えに使う共通テンプレートの `mod` とは別に扱う。

## 6. よくあるミス {toggle="true"}
	- `[l, r)` の右端を含むと思い込む。問題の `[a, b]` は `get(a-1, b)`。
	- `H[r] - H[l]` だけ引く。左側には `BASE ** (r-l)` を掛けて位置を揃える。
	- 引いた結果に `% MOD` をしない。負のまま比較すると誤判定する。
	- 比較前に長さを確認しない。`same` は長さを確かめるが、`get` 同士を直接比較する場合は自分で確認する。
	- 片方の文字列だけ `BASE` や `MOD` を変更する。別文字列間で比べるときも設定をそろえる。
	- 同じハッシュ値なら絶対に一致すると解釈する。衝突はゼロではない。
	- 元文字列の変更後に、古い前計算表を使う。
