# 9.10 グリッド問題

Source: https://www.notion.so/3e49b4299e6181688338e5bb8adf3257

---

<callout icon="💡" color="blue_bg">
	**グリッドは「各マスが頂点」のグラフ。** 上下左右の隣接マスをその場で生成すればよく、通常は隣接リスト `G` を作らなくてよい。最短手数ならBFSを使う。
</callout>
## テンプレ {toggle="true"}
	**グリッドBFS（単一始点・多始点共通）**
	```python
def grid_bfs(S, starts):
    H, W = len(S), len(S[0])
    dist = [[-1] * W for _ in range(H)]
    q = deque()

    for i, j in starts:
        if dist[i][j] == -1:
            dist[i][j] = 0
            q.append((i, j))

    while q:
        i, j = q.popleft()

        for di, dj in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            ni, nj = i + di, j + dj

            if not (0 <= ni < H and 0 <= nj < W):
                continue
            if S[ni][nj] == "#" or dist[ni][nj] != -1:
                continue

            dist[ni][nj] = dist[i][j] + 1
            q.append((ni, nj))

    return dist
	```
	- 前提：`S` は空でない `H × W` のグリッド、`#` は壁、上下左右に1手で移動できる。
	- 座標は **0-indexedの ****`(行, 列)`**。始点は盤面内の通行可能なマスとする。
	- `deque` は共通setupでimport済み。
## テンプレの使い方 {toggle="true"}
	**1つの始点からの最短距離**
	```python
dist = grid_bfs(S, [(si, sj)])
print(dist[gi][gj])  # ゴールまでの最短手数
	```
	- `dist[i][j]`：始点から `(i, j)` までの最短手数。
	- `-1`：到達できない。到達判定にも使える。
	**複数の始点からの最短距離（多始点BFS）**
	```python
starts = [(i, j) for i in range(H) for j in range(W) if S[i][j] == "H"]
dist = grid_bfs(S, starts)
	```
	全始点を距離0で同時にキューへ入れるため、`dist[i][j]` は**最も近い始点からの最短手数**になる。始点ごとにBFSを繰り返す必要はない。
## 使う場面 {toggle="true"}
	- **重みなしの最短手数・迷路の最短距離** → BFS
	- **到達可能か・連結成分** → BFS / DFS
	- **複数地点から最も近い距離・同時に広がる現象** → 多始点BFS
	- **移動コストが異なる** → BFSではなくダイクストラ法などを検討
	グリッド探索は特別なアルゴリズムではなく、普通のグラフ探索でいう `for nv in G[v]` を「隣接マスの生成」に置き換えたもの。
## 注意事項 {toggle="true"}
	- 進めるかどうかの判定は問題に合わせて変更する。上のテンプレは `#` だけを壁とし、それ以外は通行可能と扱う。
	- 移動方向が違うなら `(di, dj)` のリストを変える。斜めも許す8方向なら次のようにする。
	```python
directions = [(di, dj) for di in (-1, 0, 1) for dj in (-1, 0, 1) if (di, dj) != (0, 0)]
	```
	上記を使う場合、関数内の `for di, dj in [...]` を `for di, dj in directions:` に置き換える。
	- BFSは**1回の移動コストがすべて同じ**ときの最短手数を求める。
	- 通常の上下左右移動なら、各マスを `i * W + j` に変換して `G` を作る必要はない。
## 計算量 {toggle="true"}
	`H` 行 `W` 列のグリッドについて：
	- 時間：**O(HW)**（各マスを高々1回探索し、各マスから定数個の方向を確認）
	- 空間：**O(HW)**（`dist` とキュー）
	単一始点でも多始点でも同じ。
## よくあるミス {toggle="true"}
	- **行・列を逆にする：**`S[i][j]` の `i` は行（`0 <= i < H`）、`j` は列（`0 <= j < W`）。
	- **範囲チェックを忘れる：**Pythonでは `S[-1]` が末尾を指すため、エラーなしで誤動作することがある。
	- **2次元配列の初期化：**`[[-1] * W] * H` は同じ行を共有する。`[[-1] * W for _ in range(H)]` を使う。
	- **訪問済みの更新が遅い：**キューに追加するときに `dist` を設定し、同じマスの重複追加を防ぐ。
	- **始点の通行条件：**`S[si][sj]` が `S` や `H` でも通れる場合がある。`.` のみ通れると決めつけない。
