# 11.1 イベントソート

Source: https://www.notion.so/4129b4299e618110bdccc519dbb99ba8

---

<callout icon="💡" color="blue_bg">
	変化や質問を「座標・時刻つきのイベント」にして、ソート順に処理する。すべての地点を調べず、イベントがある場所だけを見ればよい。
</callout>
## テンプレ {toggle="true"}
	半開区間 `[l, r)` が複数あり、各地点xを含む区間の数を求める例。区間は `l < r` とする。添字は0-indexed。
	```python
def count_covering(intervals, queries):
    # 同じ座標では「終了 → 開始 → 質問」
    END, START, QUERY = 0, 1, 2
    events = []

    for l, r in intervals:
        events.append((l, START, 0))
        events.append((r, END, 0))

    for i, x in enumerate(queries):
        events.append((x, QUERY, i))

    events.sort()

    active = 0
    ans = [0] * len(queries)

    for x, kind, i in events:
        if kind == END:
            active -= 1
        elif kind == START:
            active += 1
        else:
            ans[i] = active

    return ans
	```
## テンプレの使い方 {toggle="true"}
	```python
intervals = [(1, 4), (3, 6)]
queries = [4, 1, 6, 3]

print(count_covering(intervals, queries))
# [1, 1, 0, 2]
	```
	座標順に処理しても、質問の番号iを持たせれば、答えを元の順番に戻せる。
## 使う場面 {toggle="true"}
	- 時刻・座標の順に処理すると、状態を少しずつ更新できる
	- 区間の開始・終了と、途中時点の質問をまとめて扱いたい
	- 座標が大きく、すべての地点を順に走査できない
	基本の流れは「イベントを作る → 並べる → 状態を更新する → 質問に答える」。個数なら整数、最小値ならヒープ、順位や区間集計ならFenwick Tree・セグ木などで状態を管理する。
## 注意事項 {toggle="true"}
	**同じ座標の処理順が、端点を含むかどうかを決める。**
	<table header-row="true">
<tr>
<td>区間の扱い</td>
<td>同じ座標での順序</td>
</tr>
<tr>
<td>半開区間 `[l, r)`</td>
<td>終了 → 開始 → 質問</td>
</tr>
<tr>
<td>閉区間 `[l, r]`</td>
<td>開始 → 質問 → 終了</td>
</tr>
	</table>
	閉区間に変えるときは、定数を `START, QUERY, END = 0, 1, 2` に変える。並べ替えてよいのは、入力順に処理する必要がない場合。
## 計算量 {toggle="true"}
	区間数をN、質問数をQとすると、イベント数は `2N + Q`。
	- 時間：O((N + Q) log(N + Q))
	- メモリ：O(N + Q)
## よくあるミス {toggle="true"}
	- 同じ座標のイベントの優先順位を決めない
	- 質問の元の番号を保存し忘れる
	- 半開区間と閉区間を混同する
	- 質問を処理する前に、必要な開始・終了イベントを反映し忘れる
