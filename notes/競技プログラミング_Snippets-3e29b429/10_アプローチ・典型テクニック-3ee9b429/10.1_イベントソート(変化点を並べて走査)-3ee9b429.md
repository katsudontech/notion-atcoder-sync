# 10.1 イベントソート（変化点を並べて走査）

Source: https://www.notion.so/3ee9b4299e61811095d7d4996542318d

---

<callout icon="📍" color="green_bg">
	**区間・クエリを1個ずつ処理するのではなく、位置や時刻を左から順に見て、状態が変わる地点だけをイベントとして処理する。**
</callout>
## どんなときに疑うか
- 「区間 `[L, R]` の間だけ有効」なものがたくさんある
- 各位置・各時刻で「現在有効なもの」を知りたい
- 開始時刻 / 終了時刻、入場 / 退場、追加 / 削除がある
- クエリごとに区間全体を触ると `O(NQ)` などになってしまう
- 問題を **クエリ中心 → 位置・時刻中心** に見直せそう
## 基本の考え方
区間 `[L, R]` を直接処理せず、状態が変わる2地点だけに分解する。
```plain text
[L, R] が有効
↓
L     : 開始イベント
R + 1 : 終了イベント
```
イベントを位置順にソートし、左から走査しながら現在の状態を更新する。
## 最小テンプレ：現在有効な区間数
整数位置 `1..N`、閉区間 `[L, R]` の例。
```python
N, Q = map(int, input().split())

events = []
for _ in range(Q):
    L, R = map(int, input().split())
    events.append((L, 1))
    events.append((R + 1, -1))

events.sort()

ans = [0] * N
active = 0
j = 0

for i in range(1, N + 1):
    while j < len(events) and events[j][0] == i:
        _, d = events[j]
        active += d
        j += 1

    ans[i - 1] = active

print(*ans)
```
### 計算量
- イベント数：`2Q`
- ソート：`O(Q log Q)`
- 走査：`O(N + Q)`
- 合計：`O(Q log Q + N)`
## 発想のポイント
### クエリ中心
```plain text
クエリ1の [L, R] を処理
クエリ2の [L, R] を処理
...
```
区間の長さだけ処理が必要になりやすい。
### イベント中心
```plain text
位置1で何が変わる？
位置2で何が変わる？
位置3で何が変わる？
...
```
変化しない地点では更新処理をしない。
> **「各クエリをどう高速化するか」ではなく、「見る順番を変えられないか」を考える。**
## ABC478 D 型：異なる種類の個数を管理する
単純な区間数ではなく、同じ `X` が複数区間で重なっても **1種類として数えたい** 場合。
`cnt[x]` = 現在位置を覆っている `X=x` の区間数、とする。
- `cnt[x] : 0 → 1` になったときだけ種類数を `+1`
- `cnt[x] : 1 → 0` になったときだけ種類数を `-1`
- `1 → 2` や `2 → 1` では種類数は変わらない
```python
from collections import defaultdict

N, Q = map(int, input().split())

events = []
for _ in range(Q):
    L, R, X = map(int, input().split())
    events.append((L, 1, X))
    events.append((R + 1, -1, X))

events.sort()

cnt = defaultdict(int)
active_types = 0
ans = [0] * N
j = 0

for i in range(1, N + 1):
    while j < len(events) and events[j][0] == i:
        _, d, x = events[j]

        if d == 1:
            if cnt[x] == 0:
                active_types += 1
            cnt[x] += 1
        else:
            cnt[x] -= 1
            if cnt[x] == 0:
                active_types -= 1

        j += 1

    ans[i - 1] = active_types

print(*ans)
```
## いもす法との関係
普通のいもす法も本質は同じ。
```python
diff[L] += 1
diff[R + 1] -= 1
```
これは「開始 `+1`」「終了 `-1`」というイベントを配列に置いていると考えられる。
- **座標が小さく、単純な加算だけ** → いもす法が簡単
- **座標が大きい / 疎 / 種類ごとの状態など複雑な情報を持つ** → イベントソートが使いやすい
## よくあるミス
- 閉区間 `[L, R]` の終了イベントを `R` に置く
	- 整数位置なら基本は `R + 1` に置く
- 同じ位置に複数イベントがあるのに1個しか処理しない
	- `while events[j][0] == i` でまとめて処理する
- 同じ種類が重なったとき、開始ごとに答えを増やしてしまう
	- `cnt[x] == 0` のときだけ種類数を増やす
- 連続量の区間で、同時刻の開始・終了イベントの順序を考えない
	- `[L, R)` か `[L, R]` かによって同一点での処理順が変わる
## 問題を見たときのチェック
1. 区間や期間が大量にある？
2. 各位置・時刻で状態を知りたい？
3. 区間内部では状態が変わらず、境界でだけ変化する？
4. なら **開始・終了だけをイベント化してソート** できないか考える。
