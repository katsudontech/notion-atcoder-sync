## 1. テンプレ {toggle="true"}
	**集合を合成して全要素を覆う、最小選択数のビットDP。** 以下は A23 - All Free にそのまま使えるコード。ビットDP全般に同じ遷移が使えるわけではなく、問題ごとに状態と遷移を決める。
	```python
import sys
input = sys.stdin.readline

N, M = map(int, input().split())
masks = []
for _ in range(M):
    row = list(map(int, input().split()))
    mask = 0
    for j in range(N):
        if row[j] == 1:
            mask |= 1 << j
    masks.append(mask)

INF = float("inf")
dp = [[INF] * (1 << N) for _ in range(M + 1)]
dp[0][0] = 0

for i in range(M):
    mask = masks[i]
    for s in range(1 << N):
        if dp[i][s] == INF:
            continue

        # 今回のクーポンを使わない
        dp[i + 1][s] = min(dp[i + 1][s], dp[i][s])

        # 今回のクーポンを使う
        ns = s | mask
        dp[i + 1][ns] = min(dp[i + 1][ns], dp[i][s] + 1)

ans = dp[M][(1 << N) - 1]
print(-1 if ans == INF else ans)
	```
## 2. テンプレの使い方 {toggle="true"}
	**ビットDPとは**：要素を含む・含まないという集合の情報を整数の各ビットに持たせ、その集合をDPの状態に使う方法。
	**集合の表し方**
	- 品物の添字は `j = 0, 1, ..., N - 1`。右から `j` 番目のビットが1なら、品物 `j + 1` を含む。
	- 例：`0b101` は品物1と3を含む集合。左端が品物1ではない。
	- 空集合は `0`、全体集合は `(1 << N) - 1`、集合の総数は `1 << N`（2のN乗）。
	```python
1 << j          # j番目のビットだけが1（2 ** j）
(s >> j) & 1    # j番目の要素を含むなら1
s | (1 << j)    # j番目の要素を追加
s | mask        # 2つの集合の和集合
s & mask        # 2つの集合の共通部分
s & ~(1 << j)   # j番目の要素を除く
s.bit_count()   # 含まれる要素数
	```
	**状態**：`dp[i][s]` = 先頭i枚のクーポンから選び、対象品物の和集合をちょうどsにする最小使用枚数。「先頭i枚をすべて使う」という意味ではない。
	**初期値**：`dp[0][0] = 0`。何も選ばなければ空集合を0枚で作れる。他の状態は未到達なのでINF。
	**遷移**：使わないならsのまま・枚数もそのまま。使うなら `s | mask` に移り、枚数を1増やす。どちらも次の行の現在値とminを取る。
	**なぜ最小値だけ残せるか**：同じi・同じsなら、今後使えるクーポンも覆えている品物も同じ。使用枚数が多い経路を残す必要はない。
	**答え**：`dp[M][(1 << N) - 1]`。INFなら全品物を覆えない。
## 3. 使う場面 {toggle="true"}
	- 「すべての種類を集める」「すべての条件を満たす」など、何を達成済みかを集合で管理したい。
	- 「訪問済みの頂点」「使用済みの要素」など、履歴のうち集合が今後の判断に必要。
	- 集合を構成する要素数Nが小さく、2のN乗の状態を扱える。
	**制約からの判断**：今回、クーポン枚数Mは最大100なので、クーポンを選ぶ全探索は最大2の100乗。一方、品物の種類Nは最大10なので、品物の集合は最大1024通り。小さいほうの集合を状態にする。
	Nが20程度でも候補にはなるが、`2 ** N` だけでなく「状態数 × 各状態の遷移数」とPythonのメモリ使用量を必ず確認する。
	**別の典型**：巡回・経路問題では `dp[s][v]`（訪問済み集合s、現在位置v）を使うことがある。現在位置によって次の行動や費用が変わるので、集合だけでは情報が足りない。
## 4. 注意事項 {toggle="true"}
	- **集合の合成はOR**：重複する品物があっても、すでに1のビットは1のまま。
	- **未到達はINF**：最小化DPではminをそのまま使いやすい。-1を使うなら、未到達かどうかの分岐が別途必要。
	- **前の行から次の行へ遷移**：各クーポンを高々1回選ぶことを明確にする。省メモリ化する場合も前の配列と次の配列を分けると安全。
	- **maskは各クーポンで1回だけ作る**：集合sに依存しない計算を、sのループ内で繰り返さない。
	- **空集合も状態**：クーポンを使わない遷移により、`dp[i][0] = 0` が全行に引き継がれる。
	- **二次元配列の作り方**：`[[INF] * (1 << N) for _ in range(M + 1)]` を使う。`[[INF] * (1 << N)] * (M + 1)` は各行が同じリストを参照するため不可。
	**選んだクーポンも復元したい場合**：値を改善したときに、遷移元の集合と使ったかどうかを記録する。最後の状態からiを1ずつ戻れば復元できる。この問題は枚数だけなので復元情報は不要。
## 5. 具体的な問題への適用例 {toggle="true"}
	[AtCoder・競技プログラミングの鉄則 A23 - All Free](https://atcoder.jp/contests/tessoku-book/tasks/tessoku_book_w)
	N種類の品物とM枚のクーポンがあり、すべての品物を無料で買える最小クーポン枚数を求める。不可能なら-1。制約はNが1〜10、Mが1〜100。入力はN、Mと、M行N列の0/1の情報。
	**重複を含む例**
	```plain text
3 2
1 1 0
0 1 1
	```
	```plain text
1枚目：011（品物1・2）
2枚目：110（品物2・3）
OR   ：111（全品物）
	```
	2枚で全品物を覆えるため答えは2。品物2が重複しても問題ない。
	**公式サンプル**：入力例1はクーポン1と4を使って答え2。入力例2はすべて使っても覆えない品物があるため答え-1。具体的な入力はリンク先を参照。
	**手元で確認するケース**：N=1で1枚で達成できる、全クーポンが0、同じクーポンが重複する、途中で達成して残りを使わない、対象品物が一部重複する。
## 6. 計算量 {toggle="true"}
	このページのクーポン型テンプレートの場合：
	- maskの作成：`O(MN)`
	- DP：`O(M × 2 ** N)`
	- 合計時間：`O(MN + M × 2 ** N)`
	- DP配列の空間：`O(M × 2 ** N)`。保存するmaskは追加でO(M)。
	今回の最大サイズは101行×1024列。遷移元は最大100×1024状態で、制約内で十分扱える。
	前の行と次の行だけ保持すればDP部分は `O(2 ** N)` の空間にできるが、この制約なら二次元配列で十分。まずは状態と遷移を明確にする。
	ビットDP全般の計算量が同じとは限らない。例えば `dp[s][v]` から次の頂点を全探索する典型では、時間が `O(N ** 2 × 2 ** N)` になる。
## 7. よくあるミス {toggle="true"}
	**1. 集合を引き算して直前の状態を求める【アルゴリズム理解／DPの遷移】**
	誤り：`ss = s - mask`。重複があるため、ORの結果から直前の集合は一意に決まらない。`111 - 110 = 001` だが、`011 | 110 = 111` という遷移も必要。現在の集合から `ns = s | mask` へ進める。
	負の添字にも注意。`dp[i][-1]` はエラーではなく末尾を参照するため、誤った状態を読んでしまう。
	**2. 「使わない」遷移を忘れる【DPの遷移】**
	```plain text
1 2
1
0
	```
	答えは1。最後のクーポンは不要。「使う」だけでは不要なクーポンにも枚数を加えてしまう。
	**3. 更新先の値を保持しない【添字ミス／最小化DP】**
	```python
# 誤り：比較相手が前の行
dp[i + 1][ns] = min(dp[i][s] + 1, dp[i][ns])

# 正しい：更新先にすでにある最小値を残す
dp[i + 1][ns] = min(dp[i + 1][ns], dp[i][s] + 1)
	```
	反例はN=1、M=1、クーポンが1。未到達状態をスキップしない元のコードでは、s=0で答え1を書き込んだ直後、s=1でINFに上書きされる。スキップを加えた場合でも、複数の到達可能な状態から同じnsに遷移するので、更新先とのminは必要。
	**4. 出力形式を忘れる【実装ミス】**
	未到達のINFをそのまま出力せず-1にする。提出時には `print(dp)` などの確認用出力を削除する。
	**今回の確認習慣**：同じ更新先に2通りの遷移が来たとき、先に求めた良い答えが残るかを確認する。

	**Pythonの条件式（一般に三項演算子と呼ばれる）**
	```python
print(-1 if ans == INF else ans)
	```
	形は `Trueのときの値 if 条件 else Falseのときの値`。PythonではC++やJavaScriptの `条件 ? 値1 : 値2` は使えない。
