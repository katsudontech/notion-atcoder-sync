# 4.1 動的計画法の基本

<callout icon="📝" color="yellow_bg">
	**初期条件の決め方を記入済み** — 「dp\[0\]\[0\]だけでよいか、0行目・0列目も設定するか」の判断方法を、編集距離とLCSの比較で整理する。その他の基本DPの内容は今後追記する。
</callout>
状態・遷移・初期値・計算量・復元方法を整理する。
## 1. テンプレ {toggle="true"}
	編集距離で、0行目・0列目をループ内では更新しない場合の初期化。
	```python
# S、Tは入力済みの文字列
# dp[i][j]: S[:i]をT[:j]にする最小操作回数
n = len(S)
m = len(T)
INF = float('inf')
dp = [[INF] * (m + 1) for _ in range(n + 1)]

for i in range(n + 1):
    dp[i][0] = i  # i文字を全て削除

for j in range(m + 1):
    dp[0][j] = j  # 空文字列にj文字を挿入
	```
	この初期値は編集距離の定義から決まる。他のDPにそのまま流用しない。
## 2. テンプレの使い方 {toggle="true"}
	**初期化する範囲は「dpの意味」と「ループが更新する範囲」で決まる。**
	1. dpの意味を一文で書く。
	2. 最小の状態や、片方が0の状態が何を意味するか考え、正しい値を求める。
	3. 更新先の添字を見て、ループが計算する範囲を確認する。
	4. 計算に必要なのにループでは求められない値を、事前に設定する。
	今回の編集距離では、dp\[i\]\[0\]はi文字を空にする操作回数なのでi、dp\[0\]\[j\]は空からj文字を作る操作回数なのでj。

</tr>

	siをrange(n)、tiをrange(m)で回してdp\[si + 1\]\[ti + 1\]を更新するコードは、表の?の部分しか計算しない。0行目・0列目は参照するのに更新されないため、先に設定する。
	確認の合言葉：**「そのマスを読む時点で、必要な値は正しく決まっているか？」**
## 3. 使う場面 {toggle="true"}
	「dp\[0\]\[0\]だけでよいか」「0行目・0列目も設定するか」で迷ったときに使う。
	<table header-row="true">
<tr>
<td>更新方法</td>
<td>事前に設定するもの（編集距離の例）</td>
</tr>
<tr>
<td>参照元から値を集め、1行目・1列目以降の内側だけを計算する</td>
<td>0行目・0列目の値</td>
</tr>
<tr>
<td>境界を含めた全状態から、削除・挿入・一致／変更の遷移を行う</td>
<td>dp\[0\]\[0\] = 0。残りは遷移で計算する</td>
</tr>
	</table>
	後者では、例えばdp\[0\]\[0\]から挿入でdp\[0\]\[1\] = 1、さらにdp\[0\]\[2\] = 2と進める。削除でもdp\[1\]\[0\] = 1、dp\[2\]\[0\] = 2と進める。ループで端も正しい順序で計算するので、手で設定するのは原点だけでよい。
	**「二次元DPなら必ず一行一列を設定する」という決まりはない。** 到達不能な状態は、到達不能を表す値のままにする。
## 4. 注意事項 {toggle="true"}
	**LCSと編集距離は、端の状態の意味が異なる。**
	<table header-row="true">
<tr>
<td>DP</td>
<td>dp\[i\]\[0\]</td>
<td>dp\[0\]\[j\]</td>
<td>理由</td>
</tr>
<tr>
<td>LCSの長さ</td>
<td>0</td>
<td>0</td>
<td>片方が空なら共通部分列は空</td>
</tr>
<tr>
<td>編集距離</td>
<td>i</td>
<td>j</td>
<td>空にするには削除、空から作るには挿入が必要</td>
</tr>
	</table>
	LCSで表全体を0にして作ると、その時点で0行目・0列目の初期化も済んでいる。内側はあとから計算で上書きする。LCSのテンプレに端を設定するループがないのは、初期条件を省略しているからではない。
	また、最小化DPで使うINFは「まだ経路が見つかっていない・到達不能」という扱いの値。実際には到達できる端の状態を、INFのまま参照しない。
	入力に空文字列がなくても、先頭0文字という途中の状態はDPに登場する。
## 5. 具体的な問題への適用例 {toggle="true"}
	[競技プログラミングの鉄則 B20 - Edit Distance](https://atcoder.jp/contests/tessoku-book/tasks/tessoku_book_cs)
	文字の削除・変更・挿入の最小操作回数を求める。dp\[i\]\[j\]をS\[:i\]からT\[:j\]への最小操作回数とする。
	**初期化漏れを見つける反例**
	```plain text
S = ba
T = a
正解：先頭のbを削除する1回
	```
	最初にbを削除した状態がdp\[1\]\[0\] = 1。その後、a同士は一致するので追加操作なしでdp\[2\]\[1\] = 1になる。
	dp\[0\]\[0\]だけを0にし、0行目・0列目をINFのまま内側だけ計算すると、dp\[1\]\[0\]を使う経路が利用できず、この入力で2になってしまう。
	**気付き方**：先頭を削除する例と、先頭へ挿入する例を試す。S = a、T = baも、正解は先頭にbを挿入する1回。
## 6. 計算量 {toggle="true"}
	n = len(S)、m = len(T)。編集距離を二次元表で求める場合。
	- 表の確保・INFでの初期化：時間O(nm)、空間O(nm)。
	- 0行目・0列目への値の設定：時間O(n + m)。
	- 全体のDP：時間O(nm)、空間O(nm)。
	必要な初期条件を設定しても、全体の計算量は変わらない。
## 7. よくあるミス {toggle="true"}
	- **初期値／境界値**：dp\[0\]\[0\]だけ設定し、ループで計算されない0行目・0列目を放置する。
	- **状態の意味の混同**：LCSの0埋めを、編集距離にもそのまま使う。
	- **添字**：端まで設定するにはrange(n + 1)、range(m + 1)が必要。range(n)ではdp\[n\]\[0\]が残る。
	- **更新順序**：値を読む前に、必要な状態が確定しているか確認しない。
	提出前に、dp\[1\]\[1\]など最初の更新を手で追う。今回ならdp\[0\]\[0\]・dp\[0\]\[1\]・dp\[1\]\[0\]を読むため、その3マスに正しい値があるか確認する。その後の行・列についても同じ確認を行う。
