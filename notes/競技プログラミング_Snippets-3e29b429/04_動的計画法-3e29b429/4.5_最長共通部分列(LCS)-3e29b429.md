# 4.5 最長共通部分列（LCS）

Source: https://www.notion.so/3e29b4299e6181e1af34c99c1b49637f

---

基本は「長さを求めるDP」、発展は「文字列の復元」。今回ACした3候補の最大値を取る実装を基本にする。
## 1. テンプレ {toggle="true"}
	LCSは、2つの文字列から順序を保って取り出せる共通部分列のうち最長のもの。連続していなくてもよい。例："abc" と "ac" のLCSは "ac"、長さは2。
	```python
s = input().strip()
t = input().strip()
n = len(s)
m = len(t)

# dp[i][j]: sの先頭i文字とtの先頭j文字のLCSの長さ
dp = [[0] * (m + 1) for _ in range(n + 1)]

for si in range(n):
    for ti in range(m):
        ss = dp[si + 1][ti]  # t[ti]を使わない
        tt = dp[si][ti + 1]  # s[si]を使わない
        st = 0
        if s[si] == t[ti]:
            st = dp[si][ti] + 1
        dp[si + 1][ti + 1] = max(ss, tt, st)

print(dp[n][m])
	```
## 2. テンプレの使い方 {toggle="true"}
	### 状態・初期値
	`dp[i][j]` は `s[:i]` と `t[:j]` のLCSの長さ。iとjは添字ではなく文字数。<br>片方が空なら長さは0なので、`dp[0][j]` と `dp[i][0]` は0。表全体を0で初期化する。
	この0埋めで0行目・0列目の初期化も済んでいる。「dp\[0\]\[0\]だけでよいか、端も設定するか」の判断方法と、編集距離との比較は <mention-page url="https://app.notion.com/p/3e29b4299e6181e5b0e4d8e21ded5e3a"/> を参照。
	### 遷移
	求めるマスは `dp[si+1][ti+1]`。比較する文字は `s[si]` と `t[ti]`。
	- 左の `dp[si+1][ti]`：tの今の文字を使わず、引き継ぐ。
	- 上の `dp[si][ti+1]`：sの今の文字を使わず、引き継ぐ。
	- 一致した場合の左上 `dp[si][ti]+1`：両方の今の文字を使う。
	最後の文字が違えば少なくとも片方を使わない必要がある。一致すれば両方を使う最適解が存在する。この3候補の最大値を取る。<br>先頭から二重ループを回すと、参照する左・上・左上が先に計算される。
	### 答え
	`dp[n][m]` が文字列全体のLCSの長さ。
## 3. 使う場面 {toggle="true"}
	- 2つの文字列・数列から、順序を保って共通するものを最大限取り出したい。
	- 文字を削除して、両方を同じ列にしたい。
	- 「共通」「順序を保つ」「飛ばしてよい」「最長」からLCSを疑う。
	長さnとmの積を制約から確認する。基本はO(nm)なので、両方20万などではこの方法は使えない。<br>「連続する共通部分文字列」は別の条件であり、この遷移をそのまま使わない。
## 4. 注意事項 {toggle="true"}
	- 各マスに保存するのは長さ。文字列を保存して連結するとコピーとメモリの負担が大きい。
	- 部分列では順序を変えたり、同じ位置の文字を2回使ったりできない。
	- 答えは複数ある場合がある。どれでもよいなら復元で同点の移動先は自由。辞書順最小を求める場合は別の工夫が必要。
	- 共通文字がない場合、長さ0、復元結果は空文字列。
## 5. 具体的な問題への適用例 {toggle="true"}
	[Educational DP Contest F - LCS](https://atcoder.jp/contests/dp/tasks/dp_f)
	英小文字の文字列s、tから、最長共通部分列を1つ出力する。各長さは1以上3000以下。最大約900万状態のO(nm)のDPで考える。<br>出力は長さではなく文字列なので、基本テンプレの最後の出力を以下に置き換える。
	### 発展：文字列を復元する
	右下から「最適な値を保ったまま戻れるマス」をたどる。
	- 最後の文字が一致：その文字を記録して左上へ。
	- 不一致で上と同じ値：sの最後を使わず上へ。
	- それ以外：tの最後を使わず左へ。
	```python
# 基本テンプレでdpを作った後に実行
ans = []
si = n
ti = m

while si > 0 and ti > 0:
    if s[si - 1] == t[ti - 1]:
        ans.append(s[si - 1])
        si -= 1
        ti -= 1
    elif dp[si - 1][ti] == dp[si][ti]:
        si -= 1
    else:
        ti -= 1

print(''.join(reversed(ans)))
	```
	siとtiは文字数なので、最後の文字は `s[si-1]` と `t[ti-1]`。<br>一致するときは左上の値＋1が今の値になるため、その文字を採用できる。不一致なら上か左の少なくとも一方に同じ値がある。両方同じならどちらへ戻ってもよい。<br>片方が0文字になったら終了。後ろから拾うので、最後に逆順にして連結する。
	### 復元の例
	```plain text
s = "abc", t = "ac"

(3, 2): cとcが一致 → cを記録して(2, 1)へ
(2, 1): bとaは不一致。上と同じ値 → (1, 1)へ
(1, 1): aとaが一致 → aを記録して(0, 0)へ
終了

ans = ["c", "a"]
逆順に連結して "ac"
	```
	サンプル1の "axyb" と "abyxb" では "axb" または "ayb" が正解。サンプル出力と異なっても、最長の共通部分列ならよい。
## 6. 計算量 {toggle="true"}
	n = len(s)、m = len(t)、L = LCSの長さ。
	- DP：時間O(nm)、空間O(nm)。
	- 復元：時間O(n+m)。毎回siかtiが減る。
	- 答えの保存：追加空間O(L)。反転・連結は時間O(L)。
	- 全体：時間O(nm)、空間O(nm)（n、mが1以上）。
	長さだけなら行を使い回す省メモリ化も可能だが、このページでは理解と復元への拡張を優先して二次元表を使う。
## 7. よくあるミス {toggle="true"}
	### 添字ミス
	`dp[si+1][ti+1]` の比較対象は `s[si]` と `t[ti]`。文字数と添字を混同しない。`s[si+1]` は次の文字であり、最後には範囲外になる。
	### 上・左に＋1する
	上・左は片方の文字を使わない候補なのでそのまま引き継ぐ。両方の今の文字が一致したときだけ左上から＋1。<br>例："aa" と "a" で、すでに使ったtのaを再利用して＋1すると、誤って2になる。
	### 今回の疑問：次の文字が一致したら＋1してよい？
	`s[si+1] == t[ti]` なら `dp[si+1][ti] + 1` は有効な候補。ただし更新先は `dp[si+2][ti+1]`。<br>次の行を計算するときの「左上から＋1」で処理されるため、今のマスで先回りする必要はない。＋1が禁止なのではなく、使った文字数で更新先が変わる。
	これマジで大事。
	### Python仕様・入力
	文字列は `S()` や `input().strip()` で読む。`I()` は整数用。<br>`dp[s][t]` は文字列を添字にする誤り。`dp[len(s)][len(t)]` を使う。<br>二次元配列は内包表記で行を作る。`[[0] * (m+1)] * (n+1)` は行が共有される。
	### 出力・境界値
	復元結果の反転を忘れない。dp_fでは長さだけ出力しても正解にならない。
	- "a", "a" → 長さ1
	- "a", "z" → 長さ0、空文字列
	- "aa", "a" → 長さ1
	- 同じ文字列同士 → 文字列全体
